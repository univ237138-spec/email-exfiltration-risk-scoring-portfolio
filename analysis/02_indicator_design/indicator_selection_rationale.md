# 사용자 베이스라인 지표 선정과 근거

> 대상 파일: `user_day_ldap_logon_email.csv` (330,452행, 34컬럼)
> 컬럼 정의: [user_day_ldap_logon_email_컬럼정의서.md](../../docs/data_dictionary_user_day.md)
> 작성일: 2026-09-19

## 요약

- **베이스라인 단위:** 사용자×날짜(로그인 활동일), **직전 30개 활동일**(당일 제외)
- **34개 컬럼으로 충분합니다.** 오히려 34개 모두 베이스라인을 만들 필요는 없습니다.
- 실제로 점수를 내는 지표는 **이메일 7개**(핵심 5 + 규칙형 2)와 **logon 확장 제안 2개**입니다.
- 선택적 보완: "한 메일 최대 수신자 수"(사내 대량 발송). 효과는 검증이 필요해 필수는 아닙니다.

### 판단 기준

- 지표 선정은 **정답 데이터를 보지 않고** 도메인 지식과 데이터 분포로 판단했습니다. 정답은 평가에만 씁니다.
- 아래 수치는 **점수 계산 대상 308,023행**(`active_day_seq > 10` 이고 `days_since_first >= 30`)으로 계산했습니다.

## 2. 컬럼별 근거

### ① 키·날짜 (6개): 베이스라인 없음

| 컬럼 | 역할 | 근거 |
|---|---|---|
| `user` | 키 | 기준선을 사람마다 따로 만들기 위한 기준 |
| `date` | 키 | 기준선을 오늘 이전 데이터로만 만들기 위한 순서 기준 |
| `weekday` | 맥락 | 요일마다 업무량이 다를 수 있어 확인용 |
| `is_weekend` | 필터 | 주말은 대상 행의 2%(6,393행)뿐이라, 평일 기준선과 섞을지 따로 볼지 정할 때 씀 |
| `active_day_seq` | 기준선 기간 | 직전 30개 활동일을 잡는 기준. 10 이하면 과거 기록이 부족해 기준선이 없음 |
| `days_since_first` | 점수 대상 판정 | 첫 활동일부터 30일 미만인 초반 행은 기준선이 부풀려져 점수에서 뺌 |

### ② LDAP (5개): 베이스라인 없음

| 컬럼 | 역할 | 근거 |
|---|---|---|
| `role` | 동료 비교, 해석 | 같은 직무끼리 비교하면 "이 직무는 원래 외부 메일이 많다" 같은 차이를 걸러낼 수 있음 |
| `functional_unit` | 동료 비교 | 팀을 구분하는 3단계 중 1단계 |
| `department` | 동료 비교 | 팀을 구분하는 3단계 중 2단계 |
| `team` | 동료 비교 | 3단계 중 마지막. 팀 이름이 반복되므로 위 두 컬럼과 함께 써야 함 |
| `supervisor` | 해석 | 조사할 때 보고 대상을 확인하는 용도 |

## 4. 참고할 점

- **logon 지표끼리 상관이 매우 높습니다** (0.87~0.999). 여러 PC에 로그인하는 일부 사용자(318명)가 야간 로그인도 많이 하는 것으로 보입니다. 직무(예: IT 관리자)와 관련 있을 수 있으나 확인하지 않았습니다. 사실이라면 logon 지표는 **직무별 동료 기준선**이 특히 필요합니다.
- **주말 행(2%)**은 평일 기준선과 섞을지, 제외할지 정해야 합니다.
- **`email.csv`는 원본의 약 50% 샘플**이라 이메일 지표의 하루 값이 작고 흔들립니다. 0은 "기록 없음"으로 해석합니다.
