# 사내 수신자 지표(`int_rcpt_cnt`) 제외 실험 결과

작성일: 2026-09-21 · 조건: [실험계획.md](plan.md) (결과 확인 전 고정) · 코드: [run_experiment.py](run_experiment.py)

## 결론

**`int_rcpt_cnt`를 빼도 내부자 탐지는 거의 줄지 않고, 오탐은 크게 줄었습니다.**

- 현재 등급 경계를 유지하면 주의 이상 기준으로 탐지는 **20명 → 19명**(1명 감소), 비내부자 오탐 사용자는 **462명 → 354명(−108명, −23%)** 입니다. 경보량도 19% 줄었습니다.
- 경보량을 목표(0.36%)에 맞추면 탐지는 **13명 → 19명**으로 오히려 늘고, 오탐 사용자는 **427명 → 355명**으로 줄었습니다.
- 이 지표를 넣은 목적은 시나리오 3 대응이었지만, 현재 모델에서 시나리오 3을 잡은 것은 **관심 등급의 1명(BSS0369)뿐**입니다. 주의 이상에서는 원래 0명입니다.

국내 사고 현실을 반영해 이 지표를 빼는 결정은 **성능 면에서도 손해가 거의 없고, 오탐 감소라는 이득이 큽니다**.

## 1. 이 지표가 현재 경보에 차지하는 비중 (정답 미사용)

| 항목 (보정 이후) | 값 |
|---|---:|
| `int_rcpt_cnt` 점수가 있는 날 | 1.09% (2,452 사용자·일) |
| 주의 이상 경보 946건 중 이 지표 점수가 있는 경보 | 211건 (22%) |
| 그중 **이 지표가 없으면 3점 미만이 되는 경보** | **181건 (19%)** |
| 관심 이상 3,357건 중 이 지표가 없으면 탈락 | 740건 (22%) |
| 위험 102건 중 이 지표가 없으면 탈락 | 15건 (15%) |

주의 이상 경보의 약 5건 중 1건은 사내 수신자 증가 때문에 올라온 경보입니다.

- 오탐 사용자는 모든 등급에서 17~25% 줄었습니다.

## 3. 목표 경보량에 맞춘 비교 (1.39 / 0.36 / 0.07%)

이메일_로그온_비교실험 8-2와 같은 방식입니다. 같은 정수 점수 안에서는 가장 크게 튄 지표의 z가 큰 행을 먼저 경보하고, 경계는 보정기간 분포로 고정했습니다.

| 등급 | 안 | 보정 이후 경보율 | 오탐 사용자 /930 | 탐지 /70 | 시나리오 1 / 2 / 3 |
|---|---|---:|---:|---:|---|
| 관심 이상 | 현재 (E) | 1.38% | 798 | 27 | 1 / 25 / 1 |
| | 제외 (E−int) | 1.35% | **628** | **31** | 1 / 30 / 0 |
| **주의 이상** | 현재 (E) | 0.36% | 427 | 13 | 1 / 12 / 0 |
| | 제외 (E−int) | 0.34% | **355** | **19** | 1 / 18 / 0 |
| 위험 | 현재 (E) | 0.09% | 149 | 6 | 0 / 6 / 0 |
| | 제외 (E−int) | 0.08% | **129** | **7** | 0 / 7 / 0 |

- 같은 경보량이면 사내 수신자 경보가 차지하던 자리를 **시나리오 2 내부자**(외부 발송·첨부·구직 메일 신호)가 채웁니다. 주의 이상에서 7명이 새로 잡히고 1명(TNM0961)을 놓쳤습니다.
- **주의:** 이 비교에는 보조키 효과가 섞여 있습니다. `int_rcpt_cnt`는 값이 크고 z도 크게 나오는 지표라서(1점 경계 z 3.12로 가장 높음), 현재 모델에서는 max z 보조키가 사내 수신자 경보를 앞쪽으로 끌어올립니다. 그래서 현재 모델의 목표 경보량 결과(13명)가 불리하게 나왔을 수 있습니다. 보조키와 무관한 2절 결과만 봐도 **적은 경보(765건)로 거의 같은 탐지(19명)와 훨씬 적은 오탐(354명)** 을 얻습니다. 따라서 결론 방향은 같습니다.

## 4. 로그온 별도 경보와 함께 쓸 때

`로그온_별도경보_설계.md`의 구조(이메일 주의 이상 **또는** 로그온 점수 ≥ 2)에 적용한 결과입니다.

| 구성 | 경보 사용자·일 | 하루 경보 | 오탐 사용자 /930 | 탐지 /70 | 시나리오 1 / 2 / 3 |
|---|---:|---:|---:|---:|---|
| 현재 이메일 + 로그온 | 1,753 | 5.0명 | 493 | 34 | 9 / 20 / 5 |
| **제외 이메일 + 로그온** | 1,572 | 4.5명 | **395** | 33 | 9 / 19 / 5 |

- 시나리오 3 탐지(5명)는 **로그온 경보가 담당**하므로 `int_rcpt_cnt`를 빼도 그대로입니다.
- 탐지 1명(TNM0961)을 잃고, 오탐 사용자 98명과 하루 경보 0.5명을 줄입니다.

## 5. 해석과 한계

1. **시나리오 3 대응은 로그온 경보가 더 잘합니다.** 사내 수신자 지표는 시나리오 3을 주의 이상에서 한 명도 잡지 못했습니다. 로그온 별도 경보는 5명을 잡습니다. 이 지표를 뺄 때 잃는 시나리오 3 대응력은 사실상 없습니다.
2. **오탐 감소가 큰 이유:** 사내 수신자 수는 참조(cc)를 몇 명 더 넣는 것만으로도 오르는, 업무 상황에 민감한 지표입니다(`점수지표_9개_상세설명.md` A-5). 정상 업무의 출렁임이 경보로 많이 올라왔습니다.
3. **놓치는 TNM0961(시나리오 2):** 현재 주의 이상에서 이 사람의 경보는 사내 수신자 점수가 있어야 3점을 넘습니다. 이메일 외부 유출 탐지 관점에서는 "우연히 걸린" 사례에 가깝지만, 1명 손실은 보고해야 합니다.
4. 정답 전체를 이미 본 뒤의 탐색적 비교이며 독립 검증이 아닙니다. 다만 이 제외 결정의 **근거는 국내 사고 현실(도메인)** 이고, 이 실험은 그 결정의 성능상 비용이 작다는 것을 확인한 것입니다.
5. 대시보드 기본 모델과 기존 결과 파일은 변경하지 않았습니다.

## 6. 제외 시 함께 바꿔야 할 것

| 항목 | 내용 |
|---|---|
| 핵심 지표 수 | 5개 → 4개. 점수 지표는 9개 → 8개 (이메일 6 + 로그온 2) |
| 지표별 상위 % 경계 | 현재 1% / 0.25% / 0.05%는 "목표 ÷ 지표 5개"에서 거꾸로 계산한 값([점수구간_보정_기준.md](../../03_scoring_policy/score_boundary_calibration.md)). 지표가 4개면 재계산을 검토 (주의 이상 경보율이 0.42% → 0.34%로 목표 0.36%에 오히려 더 가까워짐) |
| 대시보드 | `scoring.py`의 `CORE`에서 `int_rcpt_cnt` 제거, 시각화 05번 자료 정리 |
| 문서 | `핵심지표_5개_선정과_파생과정.md` 3절 결정을 "B. 제외"로 기록, `점수지표_9개_상세설명.md` 갱신 |
