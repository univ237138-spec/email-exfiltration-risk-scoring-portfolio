# 채널별 Isolation Forest 비교 실험 사전 기준

작성: 2026-09-22 21:08:19 (한국시간). 정답을 읽는 평가 코드를 실행하기 전에 아래 기준을 고정한다.  
근거 방안: 통계기반모델_IsolationForest_비교방안

## 1. 데이터와 기간

1. `outputs/dashboard/scored.parquet`의 점수 대상 행(`is_scored==1`)만 사용한다. 현재 모델 `email-review-v2.2`의 점수·경보를 그대로 기준 모델로 쓴다.
2. 보정기간은 2010-01~05(기준선 조건으로 실제 2010-02-01부터, 82,742행)이다. 평가기간은 2010-06-01~2011-05-17(225,281행)이다.
3. 하이퍼파라미터 선정은 보정기간 안에서만 한다. 2010-02~04를 튜닝용 학습, 2010-05를 튜닝용 검증으로 나눈다. **하이퍼파라미터 선정, 경보 경계, 전처리 결정에는 정답을 사용하지 않는다.**

## 2. 입력 특징

| 채널 | 입력 |
|---|---|
| 이메일 IF (6개) | `corp_ext_send_cnt_z`, `new_ext_rcpt_cnt_z`, `corp_ext_att_mail_cnt_z`, `personal_att_mail_cnt_z`, `jobkw_mail_flag`, 새로운 야간 메일(`night_mail_flag==1 & night_mail_past30==0`) |
| 로그온 IF (2개) | `other_pc_logon_cnt_z`, `night_logon_cnt_z` |

- **주 설정: z를 0 아래에서 자른다(`max(z,0)`).** 보정기간 이메일 z의 55~70%가 음수(평소보다 적은 활동)다. 그대로 넣으면 IF가 드문 감소도 이상으로 본다. 유출·내부자 행동 가설과 현재 모델은 모두 증가만 위험 신호로 본다. 따라서 도메인 근거로 증가 방향만 남기도록 사전에 결정한다.
- 원 z를 그대로 넣는 설정은 **민감도 분석**으로만 보고하며 주 결과를 대체하지 않는다.
- 사용자 ID, 날짜, 직무, 정답 정보는 입력하지 않는다. IF는 특징별 최소~최대 범위에서 무작위 분할하므로 척도 변환은 하지 않는다.

## 3. 하이퍼파라미터 탐색 (정답 미사용)

- 탐색 격자: `max_samples` ∈ {256, 1024, 4096, 16384}, `n_estimators` ∈ {100, 300, 1000}. `max_features=1.0`, `bootstrap=False`로 고정한다. `contamination`은 경계를 직접 정하므로 사용하지 않는다.
- 우리 데이터에 맞춘 이유:
  - 목표 경보율이 약 0.2%로 매우 낮다. 기본값 `max_samples=256`은 트리 깊이 한도가 8이다. 극단 꼬리의 행들이 같은 경로 길이로 잘려 **경보 경계 부근 동점과 순위 불안정**이 생길 수 있다. 그래서 더 큰 표본 크기를 후보로 포함한다.
  - 로그온은 서로 다른 입력 조합이 적어(보정기간 4,674개) 동점이 불가피하다. 동점률을 진단 지표로 본다.
  - 트리 수가 적으면 난수 시드에 따라 상위 0.2% 선정이 흔들린다. 시드 안정성을 최우선 기준으로 둔다.
- 각 후보를 시드 0~4로 5회 학습한다(2010-02~04). 채널별 목표 경보율(현재 모델의 보정기간 경보율: 이메일 주의 이상 0.2369%, 로그온 경보 0.2079%)에 해당하는 학습 점수 분위수를 경계로 삼는다. 이 경계를 2010-05에 적용한다.
  - **S1 시드 안정성:** 5개 시드의 5월 경보 집합 간 평균 쌍별 Jaccard.
  - **S2 경보율 이전 오차:** 5월 경보율/목표 경보율 −1의 절대값 평균.
  - **S3 경계 동점률:** 학습 행 중 경계 점수와 정확히 같은 점수를 가진 비율(진단용).
- 선정 규칙(채널별): S1이 최고값−0.02 이상이고 S2가 최저값+0.10 이하인 후보 중 계산량(`n_estimators × max_samples`)이 가장 작은 것을 고른다. 조건을 만족하는 후보가 없으면 S1 최고 후보를 고른다.

## 4. 최종 모델과 경보 경계

- 선정한 하이퍼파라미터로 보정기간 전체(2010-02~05)를 시드 0으로 학습한다. 이상점수는 `-score_samples`(클수록 이상)이다.
- 채널별 경계는 보정기간 학습 점수에서 위 목표 경보율에 해당하는 분위수다. `점수 ≥ 경계`이면 경보다. 최종 조사 대상은 **이메일 IF 경보 OR 로그온 IF 경보**다. 두 IF 점수는 더하지 않는다.
- 경계와 모델 설정은 정답을 열기 전에 `frozen_if_calibration.json`에 저장한다. 평가 결과를 보고 다시 조정하지 않는다.

## 5. 평가 (정답 사용, 사후 비교)

1. **고정 경계 비교:** 평가기간에 저장된 경계를 적용한다. 사건기간 탐지 내부자 고유 인원(/70), 비내부자 오탐 고유 인원(/905), 경보 사용자·일, 사용자·일 혼동행렬, 시나리오별 탐지를 현재 모델과 비교한다.
2. **동일 조사량 비교:** 평가기간 현재 채널별 경보량(이메일 498, 로그온 344 사용자·일)만큼 각 IF의 상위 행을 뽑아 OR로 결합한다. 경계 점수에 동점이 있으면 seed 20260922로 100회 무작위 선택해 평균·최소·최대를 보고한다. 이 방식은 사후 순위 비교이며 운영 경계가 아니다.
3. **탐지자 변화:** 현재 모델만 탐지, IF만 탐지, 둘 다 탐지한 내부자를 나열한다.
4. **시드 강건성:** 최종 설정으로 시드 0~4를 각각 학습·보정한 고정 경계 결과의 범위를 보고한다.
5. **선정 이유 설명:** IF만 경보한 날과 현재 모델만 경보한 날의 지표 프로필(특징별 평균, 가장 큰 z 지표 분포)을 비교한다.
6. **민감도:** 원 z(자르지 않음) 설정의 고정 경계 결과를 참고로 보고한다.

## 6. 개인 사용자 사례표

평가 후 아래 규칙으로 사례 사용자를 고른다. 사례는 성능 우열의 근거가 아닌 설명 자료다.
- 사례 A: IF만 사건기간 탐지한 내부자 중 IF 사건기간 경보일이 가장 많은 사용자.
- 사례 B: 현재 모델만 사건기간 탐지한 내부자 중 현재 모델 사건기간 경보일이 가장 많은 사용자.
- 사례 C: 비내부자 중 IF 경보일이 가장 많은 사용자.
- 해당자가 없는 사례는 생략한다. 동률이면 사용자 ID 순으로 고른다. 다른 사용자는 `python case_table.py <USER>`로 같은 표를 만든다.

## 7. 한계

기존 정답으로 지표와 정책을 검토한 이력이 있어 이 결과는 독립 홀드아웃 검증이 아닌 사후 비교다. IF 이상점수는 내부자일 확률이 아니다. 현재 모델과 운영 산출물은 변경하지 않는다.
