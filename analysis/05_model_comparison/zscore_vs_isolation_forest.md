## 2. 비교 대상 두 모델

### 2.1 기존 통계 점수 모델 (v2.2)

**분석 단위:** 사용자·일. 개인 기준선은 당일을 제외한 직전 30개 활동일이다.

```
z = (오늘 값 − 직전 30활동일 평균) / max(직전 30활동일 표준편차, 1)
```

**점수 대상 조건:** 과거 활동일 10일 이상, 첫 활동 후 30일 이상. 미충족 22,429행은 점수화하지 않는다(0점 처리 아님).

**건수형 지표의 점수:** 2010-01~05 보정기간 z 분포의 99%, 99.75%, 99.95% 분위수를 넘을 때마다 1점씩, 최대 3점이다.

| 채널 | 지표 | 1점 경계 | 2점 경계 | 3점 경계 |
|---|---|---:|---:|---:|
| 이메일 | 회사계정 외부 발송 `corp_ext_send_cnt` | 2.3667 | 3.1667 | 3.8377 |
| 이메일 | 신규 외부 수신자 `new_ext_rcpt_cnt` | 2.6667 | 3.6667 | 4.6667 |
| 이메일 | 회사계정 외부 첨부 `corp_ext_att_mail_cnt` | 1.6445 | 1.9000 | 2.7918 |
| 이메일 | 개인계정 첨부 `personal_att_mail_cnt` | 2.3000 | 3.1008 | 3.9482 |
| 로그온 | 다른 PC 로그온 `other_pc_logon_cnt` | 1.0000 | 1.5671 | 1.8871 |
| 로그온 | 야간 로그온 `night_logon_cnt` | 0.9333 | 1.8136 | 2.3358 |

**규칙형 지표의 점수**

| 지표 | 점수 |
|---|---|
| 구직 키워드 메일 `jobkw_mail_flag` | 발생 시 2점 |
| 새로운 야간 메일 | `night_mail_flag==1` 이면서 `night_mail_past30==0`이면 1점 |

**이메일 등급**

```
이메일 점수 = max(외부발송 점수, 외부첨부 점수) + 신규 외부 수신자 + 개인계정 첨부 + 구직 키워드 + 새로운 야간 메일
관심 ≥ 2점, 주의 ≥ 3점, 위험 ≥ 5점
```

외부 첨부는 외부 발송의 부분집합이므로 둘 중 최댓값 하나만 반영한다.

**로그온 경보**

```
로그온 점수 = max(다른 PC 로그온 점수, 야간 로그온 점수)
경보 = (로그온 점수 == 3) OR (로그온 점수 == 2 AND 두 z의 최댓값 ≥ 1.9443)
```

**최종 조사 대상:** 이메일 주의 이상 OR 로그온 경보. 두 점수는 더하지 않는다.

**특징:** 개인 기준선 대비 **증가**에만 점수를 준다. 지표별 점수로 이유를 바로 설명할 수 있다.

### 2.2 채널별 Isolation Forest 모델

**원리:** 무작위 분할 트리로 각 관측을 고립시키는 데 필요한 평균 분할 횟수를 잰다. 적은 횟수로 고립되는 행(드문 행)일수록 이상점수가 높다.

**구조:** 기존 모델의 채널 구조를 유지하고 점수 산출 방식만 바꾼다.

```
이메일 IF(6개 입력) → 이메일 이상점수 → 경계 이상이면 이메일 경보
로그온 IF(2개 입력) → 로그온 이상점수 → 경계 이상이면 로그온 경보
최종 조사 대상 = 이메일 IF 경보 OR 로그온 IF 경보   (이상점수는 더하지 않음)
```

**입력 특징:** 기존 0~3점이 아니라 점수화 전의 z와 규칙 발생 여부를 쓴다.

| 채널 | 입력 | 형태 |
|---|---|---|
| 이메일 | `corp_ext_send_cnt_z` | 연속, 0 미만은 0으로 자름 |
| 이메일 | `new_ext_rcpt_cnt_z` | 연속, 0 미만은 0으로 자름 |
| 이메일 | `corp_ext_att_mail_cnt_z` | 연속, 0 미만은 0으로 자름 |
| 이메일 | `personal_att_mail_cnt_z` | 연속, 0 미만은 0으로 자름 |
| 이메일 | `jobkw_mail_flag` | 0/1 |
| 이메일 | 새로운 야간 메일 (`night_mail_flag==1 & night_mail_past30==0`) | 0/1 |
| 로그온 | `other_pc_logon_cnt_z` | 연속, 0 미만은 0으로 자름 |
| 로그온 | `night_logon_cnt_z` | 연속, 0 미만은 0으로 자름 |

- 사용자 ID, 날짜, 직무, 정답 정보는 입력하지 않았다.
- IF는 특징별 최소~최대 범위에서 무작위로 분할하므로 표준화 같은 척도 변환은 하지 않았다.
- 이상점수는 `-score_samples(x)`로 정의했다. 값이 클수록 이상이다.

### 2.3 두 모델의 차이

| 구분 | 기존 통계 모델 | 채널별 IF |
|---|---|---|
| 판단 방식 | 지표별 분위수 경계를 넘으면 점수, 점수 합으로 등급 | 입력 조합이 학습 데이터에서 얼마나 드문지 |
| 결과 | 정수 점수·등급 | 연속 이상점수 + 경계 |
| 지표 비중 | 사람이 정한 규칙(구직 키워드 2점 등) | 데이터의 희소성이 비중을 결정 |
| 단일 지표 급증 | 해당 지표 점수로 직접 반영 | 여러 특징 중 무작위 선택으로 희석될 수 있음 |
| 여러 지표 동시 상승 | 점수 합으로 반영 | 조합 자체가 드물면 강하게 반영 |
| 설명 | 지표별 점수로 즉시 설명 | 지표 프로필로 사후 추정 필요 |
| 결과 해석 | 조사 우선순위 | 드문 정도. 내부자일 확률이 아님 |

## 4. IF 하이퍼파라미터 조정 (정답 미사용)

### 4.1 데이터 특성에 따른 설계 판단

| 데이터 특성 | 보정기간 관측값 | 설계 판단 |
|---|---|---|
| 음수 z가 대부분 | 이메일 z 55.3~69.5%가 음수, 로그온 10.6~23.1% | 음수를 0으로 잘라 **증가만** 입력 (도메인 근거로 사전 결정) |
| 목표 경보율이 매우 낮음 | 이메일 0.2369%, 로그온 0.2079% | 극단 꼬리의 순위가 중요 → 기본 표본 크기 256(트리 깊이 한도 8) 외에 큰 표본 후보 포함 |
| 로그온 입력 조합이 적음 | 서로 다른 값 조합 4,674개 (이메일 60,842개) | 경계 동점 가능성 → 동점률을 진단 지표로 확인 |
| 규칙형 신호가 매우 드묾 | 구직 키워드 0.030%, 새로운 야간 메일 0.123% | 0/1 그대로 입력 (IF가 희소성으로 비중을 정함) |
| 시드에 따른 변동 | 상위 0.2%만 선정 | 시드 안정성을 최우선 선정 기준으로 |

### 4.2 탐색 방법

- **격자:** `max_samples` ∈ {256, 1024, 4096, 16384} × `n_estimators` ∈ {100, 300, 1000}. 채널별로 12개씩, 총 24개 후보를 탐색했다.
- **고정한 값:** `max_features=1.0`, `bootstrap=False`. `contamination`은 쓰지 않았다(경계를 직접 정하므로).
- **절차:** 후보마다 시드 0~4로 5회 학습(2010-02~04)했다. 학습 점수에서 목표 경보율에 해당하는 분위수를 경계로 잡고 5월에 적용했다.

| 기준 | 정의 | 용도 |
|---|---|---|
| S1 시드 안정성 | 5개 시드의 5월 경보 집합 간 평균 쌍별 Jaccard | 1순위 |
| S2 경보율 이전 오차 | 평균 \|5월 경보율 / 목표 경보율 − 1\| | 2순위 |
| S3 경계 동점률 | 학습 점수 중 경계값과 같은 비율 | 진단 |

**선정 규칙 (사전 고정):** S1 ≥ (최고 S1 − 0.02) 이고 S2 ≤ (최저 S2 + 0.10)인 후보 중 계산량(`n_estimators × max_samples`)이 가장 작은 것을 고른다.

### 4.5 조정 결과 해석

- **이메일은 큰 표본이 필요했다.** 기본값 256×100에서는 시드만 바꿔도 5월 경보 집합의 약 40%가 바뀌었다(S1 0.60). 입력 6개와 목표율 0.24% 조건에서는 극단 꼬리를 세밀하게 나눌 트리 깊이와 트리 수가 모두 필요했다. 16384×1000에서 S1이 0.96이 됐다.
- **로그온은 기본 표본 크기로 충분했다.** 입력 2개, 값 조합 4,674개로 공간이 단순해 큰 표본의 이득이 없었다. 오히려 1024·16384에서는 5월 경보율 이전 오차가 커졌다.
- 트리 수 1000은 두 채널 모두에서 안정성을 높였다.
- 경계 동점률은 사실상 0이어서 동점 처리가 결과에 영향을 주지 않았다.

## 5. 평가 방법

- **사건기간 탐지:** 내부자가 자신의 사건기간(start~end) 안에 경보를 한 번 이상 받으면 탐지다. 고유 인원으로 세며, 분모는 70명이다.
- **비내부자 오탐:** 평가기간에 경보를 한 번 이상 받은 비내부자 고유 인원이다. 분모는 905명이다.
- **사용자·일 혼동행렬:** 사건기간 안 사용자·일을 양성으로 본다. 사건기간을 대리 정답으로 쓰는 한계가 있다.
- **고정경계 비교:** 보정기간에 고정한 경계를 평가기간에 그대로 적용한다. 실제 운영 방식에 해당한다.
- **동일 조사량 비교:** 기존 모델의 평가기간 채널별 경보량(이메일 498, 로그온 344)만큼 IF 상위 행을 골라 OR로 결합한다. 경계 동점은 seed 20260922로 100회 무작위 선택한다. 사후 순위 비교이며 운영 경계가 아니다.
- 이상점수 숫자(기존 3점 vs IF 0.66)는 단위가 달라 직접 비교하지 않는다.

## 7. 두 모델이 다른 날을 고른 이유

### 7.1 불일치 경보일 지표 프로필 (평가기간, 통합 기준)

"1점 수준"은 기존 모델의 1점 경계 이상인 z 또는 규칙 발생을 뜻한다.

| 항목 | 둘 다 경보 | 기존만 경보 | IF만 경보 |
|---|---:|---:|---:|
| 사용자·일 | 474 | 368 | 511 |
| 사건기간 안 | 29 | 9 | 103 |
| 비내부자 | 407 | 330 | 385 |
| 1점 수준 지표 평균 개수 | 1.94 | 1.49 | 1.33 |
| 외부 발송 1점 수준 비율 | 32.1% | 26.9% | 8.2% |
| 신규 외부 수신자 | 16.0% | 21.2% | 6.7% |
| 외부 첨부 | 24.9% | 19.0% | 11.2% |
| 개인계정 첨부 | 15.6% | 34.5% | 5.3% |
| 다른 PC 로그온 | 49.2% | 25.8% | 18.4% |
| 야간 로그온 | 49.6% | 21.2% | 20.4% |
| **구직 키워드** | 5.5% | 0.0% | **31.9%** |
| **새로운 야간 메일** | 0.6% | 0.0% | **30.7%** |

### 7.2 해석

1. **구직 키워드:** 기존 모델에서는 2점이라 단독으로는 관심 등급이고 조사 대상(주의 3점)이 아니다. 이 날이 주의가 되려면 다른 이메일 지표가 1점 이상 필요하다. IF에서는 보정기간 발생률 0.03%인 희귀 이진값이라 곧바로 고립되어 **항상 경보**가 된다. 평가기간 구직 키워드 189일 중 IF 경보는 189일, 기존 이메일 주의 이상은 26일이다.
2. **새로운 야간 메일:** IF에서 160일이 경보됐지만 그중 95.6%가 비내부자였다. IF 오탐 증가의 주요 원인이다.
3. **한 지표만 크게 오른 날에는 IF가 약하다.** 기존 모델만 경보한 이메일 256일의 IF 점수는 보정기간 상위 0.45%(중앙값)로, 경계(0.24%)에 조금 못 미쳤다. IF는 분할마다 6개 특징 중 하나를 무작위로 고르므로, 한 특징의 극단값이 다른 특징의 평범한 값에 희석된다.
4. **로그온 IF는 두 지표가 함께 오른 날에 반응한다.** 야간 로그온만 급증하는 시나리오 1은 놓쳤다. 반대로 다른 PC 로그온과 야간 로그온이 반복해서 함께 오르는 비내부자(예: JAV0361)는 더 자주 경보했다.

### 7.3 사후 분해 — 채택 후보 아님

개선이 어디서 왔는지 설명하려고 정답을 본 뒤 두 조합을 확인했다.

| 조합 | 경보 사용자·일 | 사건기간 탐지 | 비내부자 오탐 |
|---|---:|---:|---:|
| 기존 모델 OR 구직 키워드 단독 발생 | 1,005 | 40명 | 330명 |
| IF 이메일 OR 기존 로그온 | 1,007 | 39명 | 336명 |

두 조합 모두 IF 고정경계보다 탐지가 많다. 즉 IF의 이득은 알고리즘 자체보다 구직 키워드 비중에서 나왔다. 두 조합은 정답을 본 뒤 만든 것이므로 이 결과로 규칙을 바꾸면 안 되며, 설명 자료로만 쓴다([점수가중치를 정답으로 맞추지 않는 이유](../03_scoring_policy/why_not_label_fitted_weights.md) 참고).

다른 PC 로그온 5건과 야간 로그온 4~5건이 반복적으로 **함께** 나타나며, 업무 패턴일 가능성이 높다. IF는 이런 동시 상승을 매우 드물다고 보고 기존 모델이 관심에 그친 날도 경보했다. 로그온 IF가 오탐 **인원**을 줄였더라도, 이런 사용자에게는 경보가 더 잦아진다. 전체 날짜표는 `case_JAV0361.csv`에 있다.

## 9. 종합 판단

| 판단 항목 | 결론 |
|---|---|
| IF로 기존 모델 대체 | **근거 부족.** 동일 조사량 이점(+4명, −42명)이 있지만 대부분 구직 키워드 비중에서 나왔고, 기존 탐지자 7명을 잃는다 |
| 이메일 채널 | IF가 기존 모델의 약점을 드러냄: **구직 키워드 단독 발생이 조사 대상 경계(3점)에 닿지 않음** |
| 로그온 채널 | **기존 규칙 유지가 합리적.** IF는 단일 지표 급증(시나리오 1)을 놓친다 |
| 하이퍼파라미터 | 이메일 16384×1000, 로그온 256×1000. 시드 강건성 확인 |
| 단일 8개 지표 IF (추가 실험안) | 단일 지표 급증이 더 희석될 가능성이 커서 우선순위 낮음 |

**다음 검토 제안**
- 구직 키워드의 점수(현재 2점)와 조사 대상 경계의 관계는 국내 사례, 구직 후 유출의 비중 같은 **도메인 근거**로 다시 판단할 수 있다. 이번 정답 대조 결과(§7.3)를 직접 근거로 삼으면 정답에 맞춘 조정이 된다.
- IF를 운영 모델이 아닌 **보조 신호**(기존 모델이 관심 등급으로 둔 날 중 IF 상위인 날을 참고 표시)로 쓰는 방안은 별도 사전 기준을 세워 검토할 수 있다.

## 10. 한계

1. 기존 정답으로 지표와 정책을 검토한 이력이 있어 **독립 홀드아웃 검증이 아닌 사후 비교**다.
2. IF 이상점수는 **내부자일 확률이 아니다.** 드문 정도를 뜻하며 정상 업무 변화도 높게 나올 수 있다.
3. 개별 경보 이유는 지표 프로필로 추정했다. SHAP 같은 모델 내부 기여도는 계산하지 않았다.
4. 보정기간(2~5월)이 4개월로 짧다. 구직 키워드 발생률이 평가기간과 달라 고정경계 경보량이 목표보다 커졌다.
5. 사용자·일 혼동행렬은 사건기간 전체를 양성으로 보는 대리 정답이다. 사건기간 중 정상 활동일도 양성에 포함된다.
6. 하이퍼파라미터 선정 기준(시드 안정성, 경보율 이전)은 정답과 무관한 안정성 기준이다. 탐지 성능을 최대화하는 설정이라는 보장은 없다.
