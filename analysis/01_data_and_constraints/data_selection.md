# 이메일 내부 유출자 탐지 프로젝트: 사용할 데이터셋 판단

> 프로젝트 목표: 사내 이메일로 수상한 행동을 하는 내부 유출자를 탐지하고 위험 점수를 산출한다.
> 검토 대상: LDAP, `logon.csv`, `email.csv`, `http.csv`, `device.csv`, `file.csv`
> 작성일: 2026-09-19

## 요약

- 점수 산출의 핵심 데이터는 **email + LDAP + logon** 3개입니다.
- http는 정답 증거가 약 5%만 남아 있어 **보조 참고용**으로만 쓸 수 있고, file은 **제외**를 권장합니다.
- device는 정답 증거가 완전하지만 이메일이 아닌 USB 경로라서 **범위 결정이 필요**합니다.
- r4.2 내부자 70명 중 **시나리오 1(30명)은 이메일 흔적이 없습니다**. 이메일만으로 찾을 수 있는 내부자는 이론상 최대 40명이고, 그 메일 증거도 절반만 남아 있습니다.

## 1. 파일별 판단

| 파일 | 판단 | 이유 |
|---|---|---|
| **email.csv** | ✅ 핵심 | 탐지 대상 행동 그 자체 |
| **LDAP** | ✅ 핵심 | 회사/개인 메일 구분(`from` = LDAP `email`), 직무·팀으로 동료 비교 |
| **logon.csv** | ✅ 핵심 | 사용자×날짜 행 기준(330,452행), 야간 로그인, 다른 사람 PC 로그인 |
| http.csv | ⚠️ 보조만 | 조인은 완벽하지만 정답 이벤트 3,860건 중 **183건(약 5%)만** 남아 있어 점수에 넣어도 검증할 수 없음 |
| device.csv | ⚠️ 범위 결정 필요 | 정답 이벤트 2,785건이 전부 있어 가장 강한 신호. 단, 이메일이 아닌 USB 경로 |
| file.csv | ❌ 제외 권장 | 정답 이벤트 10건뿐이고, 메일 첨부와 연결 불가 |

정답 이벤트 포함 현황:

|---|---:|---:|---|
| logon.csv | 854,859 | 198 / 198 | 전체 |
| device.csv | 405,380 | 2,785 / 2,785 | 전체 |
| file.csv | 445,581 | 10 / 10 | 전체 |
| email.csv | 1,314,400 | 238 / 470 | 원본의 약 50% |

## 2. 정답 데이터로 본 이메일 탐지 가능 범위

`labels/answers/insiders.csv` 기준 r4.2 내부자는 70명입니다.

- 아래 이벤트 특성은 **개발용 내부자 35명**(사건 시작 2010-10-01 이전)의 요약입니다. 출처는 `dev_insider_event_profile.json`입니다.
- 검증용(holdout) 내부자의 상세 파일은 기존 규칙대로 열지 않았습니다.

| 시나리오 | 전체 인원 | 개발용 인원 | 정답 이벤트 종류 | 이메일 흔적 |
|---|---:|---:|---|---|
| 1 | 30명 | 14명 | 야간 로그인 + USB + 위키리크스 접속 | **없음** |
| 2 | 30명 | 15명 | 구직 사이트 + USB + **경쟁사로 메일 발송** | 회사 계정(dtaa.com)으로 발송 |
| 3 | 10명 | 6명 | 키로거 + USB + **대량 메일** | 회사 계정으로 **사내** 수신자에게 발송 |

### 2-1. 시나리오별 이메일 특성 (개발용)

| 항목 | 시나리오 2 | 시나리오 3 |
|---|---|---|
| 정답 메일 수 | 218건 | 30건 |
| 발신 도메인 | dtaa.com 100% | dtaa.com 100% |
| 주요 수신 도메인 | raytheon.com 51, northropgrumman.com 46, dtaa.com 44, hp.com 43, lockheedmartin.com 41, harris.com 22 | dtaa.com 87 |
| 근무시간 외 비율 | 2.3% | 10% |
| 평균 첨부 수 | 0.35 | 0.27 |
| 메일당 평균 수신자 수 | 1.13 | 2.9 |

### 2-2. 의미

- **시나리오 1(30명)은 이메일로 탐지할 수 없습니다.** 이메일만으로 찾을 수 있는 최대치는 시나리오 2·3의 40명입니다.
- **메일 증거도 절반만 있습니다.** email.csv는 원본의 약 50% 샘플이라, 정답 메일 470건 중 238건만 있습니다.
- **시나리오 2**는 회사 계정으로 경쟁 방산업체에 보내는 메일이라 현재 행동지표(`corp_ext_send_cnt`, `new_ext_rcpt_cnt`, 구직 키워드 메일)와 맞습니다. 구직 사이트 접속 등 평소에 드문 행동은 아니므로 "평소보다 늘었는가"로 봐야 합니다.
- **시나리오 3**은 **사내** 발송이라 현재 외부 발송 중심 지표로는 잡기 어렵습니다. 개발용 6명의 정답 메일은 30건, 메일당 수신자 2.9명(사내 수신 87건)으로 한 통당 규모가 아주 크지는 않습니다. 사내 수신자 수 급증 지표가 따로 필요하지만, 효과는 실제 데이터로 확인해야 합니다.
- 시나리오 2·3 모두 **회사 계정**으로 보냈습니다. 개인 메일 첨부 지표(`personal_att_mail_cnt`)는 정답 메일과 직접 맞지 않습니다.

## 3. 선택지

| 선택지 | 데이터 | 장점 | 한계 |
|---|---|---|---|
| **A. 이메일 중심** | email + LDAP + logon | 프로젝트 주제와 정확히 맞음 | 탐지 가능 내부자 최대 40명, 메일 증거 절반 |
| **B. 이메일 중심 + 장치 보조** | A + device | 정답 이벤트가 완전해 검증력이 가장 좋음 | "이메일 유출" 주제와 어긋남 |

참고로 기존 적합성 판단 문서는 범위를 logon·device·file 사용자 단위 위험 점수로 넓히자고 제안했습니다.

## 4. 권장안

**A(이메일 중심)로 진행하되, 설계서에 다음을 명시합니다.**

1. **평가 대상 명시:** 탐지 성능은 시나리오 2·3의 40명 기준으로 평가합니다. 시나리오 1은 이메일로 탐지할 수 없는 범위로 적습니다.
2. **사내 대량 발송 지표 추가:** 하루 사내 수신자 수 급증 등 시나리오 3에 대응하는 지표를 추가합니다.
3. **http는 점수에서 제외:** 정답 증거가 약 5%만 남아 있으므로 해석·참고용으로만 씁니다.
4. **LDAP 퇴사 시점은 검증용으로만:** 퇴사 여부는 사후 정보이므로 점수 산출에 넣지 않습니다.

## 5. 결정이 필요한 것

- 프로젝트 범위를 이메일로 유지할지(A), device를 보조로 넣을지(B)
- 평가 기준을 70명 전체로 할지, 이메일로 탐지 가능한 40명으로 할지
