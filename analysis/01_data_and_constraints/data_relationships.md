# LDAP·logon·email·http·device·file 데이터 관계 개요

> 대상 파일: LDAP (18개 월별 파일), `logon.csv`, `email.csv`, `http.csv`, `device.csv`, `file.csv`
> 작성일: 2026-09-19
> 이 문서는 같은 폴더의 관계 분석 문서 5개를 한 장으로 요약한 것입니다. 상세 수치와 재현 코드는 각 문서를 참고하세요.

## 요약

6개 데이터는 **LDAP(누구인가) → logon(언제 PC를 켰나) → 4개 활동 로그(무엇을 했나)** 순서의 계층 구조입니다.

- 5개 로그의 모든 사용자가 LDAP에 있습니다.
- 4개 활동 로그의 99.99%는 로그인한 상태에서 발생했습니다.
- 파일 이벤트는 99.56%가 이동식 장치가 연결된 동안 발생했습니다.
- email과 http는 같은 사람·같은 PC의 기록이지만 활동량은 서로 독립적입니다.

## 1. 전체 구조

```
LDAP  ─ 인사 명단 (1,000명 → 845명, 월별 18개 파일)
 │   user_id = user
 ▼
logon.csv  ─ 로그인 구간 (Logon ~ Logoff)
 ├── email.csv   메일 발송       ←─ from = LDAP email (회사/개인 메일 구분)
 ├── http.csv    웹 접속
 └── device.csv  이동식 장치 연결 ~ 해제
        └── file.csv  장치 연결 중 파일 이벤트
```

## 2. 파일별 역할

| 파일 | 한 행의 의미 | 행 수 | 사용자 | 역할 |
|---|---|---:|---:|---|
| LDAP | 한 달 시점의 직원 1명 | 월 845~1,000 | 1,000명 | 신원·소속·회사 메일·재직 기간 |
| logon.csv | 로그인 또는 로그아웃 1건 | 854,859 | 1,000명 | 모든 활동의 바탕이 되는 로그인 구간 |
| email.csv | 메일 1건 | 1,314,400 | 1,000명 | 메일 발송 행동 |
| http.csv | 웹 접속 1건 | 1,422,900 | 1,000명 | 웹 접속 행동 |
| device.csv | 장치 연결 또는 해제 1건 | 405,380 | 265명 | 이동식 장치 사용 |
| file.csv | 파일 이벤트 1건 | 445,581 | 264명 | 장치 연결 중 파일 활동 |

### 파일별 컬럼

| 파일 | 컬럼 |
|---|---|
| LDAP | `employee_name`, `user_id`, `email`, `role`, `business_unit`, `functional_unit`, `department`, `team`, `supervisor` |
| logon.csv | `id`, `date`, `user`, `pc`, `activity` (`Logon` / `Logoff`) |
| email.csv | `id`, `date`, `user`, `pc`, `to`, `cc`, `bcc`, `from`, `size`, `attachments`, `content` |
| http.csv | `id`, `date`, `user`, `pc`, `url`, `content` |
| device.csv | `id`, `date`, `user`, `pc`, `activity` (`Connect` / `Disconnect`) |
| file.csv | `id`, `date`, `user`, `pc`, `filename`, `content` |

## 3. 관계별 결과

| 관계 | 연결 방법 | 결과 | 상세 문서 |
|---|---|---|---|
| **LDAP → 모든 로그** | `user_id` = `user` | 5개 로그의 모든 사용자가 LDAP에 있음. 퇴사자는 명단에서 처음 빠진 달에 활동이 끝남(98.1%) | `LDAP_활동로그_관계_분석.md` |
| **LDAP → email** | LDAP `email` = 메일 `from` | 일치하면 회사 메일(62.3%), 다르면 개인 메일(37.7%) | `LDAP_활동로그_관계_분석.md` |
| **logon → 4개 활동 로그** | `user` + `pc` + 시간 | 모든 활동의 99.99%가 로그인 상태에서 발생. 로그인 없이 일어난 활동 0건 | `logon_활동로그_관계_분석.md` |
| **device → file** | `user` + `pc` + 시간 | 파일 이벤트의 99.56%가 장치 연결 중 발생. 거의 1:1로 맞물림 | `device_file_관계_분석.md` |
| **email ↔ http** | `user` + 날짜 | 사용자-PC 1,000쌍 동일. 활동량은 독립적이고 구직 신호만 약하게 연결 | `email_http_관계_분석.md` |
| **email ↔ file** | `user` + 날짜 | 첨부파일과 연결 불가. 관계 거의 없음 | `file_email_관계_분석.md` |

## 4. 공통으로 알아 둘 점

- **이벤트 ID는 조인 키가 아닙니다.** `id`는 파일마다 따로 매긴 번호라 파일 사이에 겹치는 값이 없습니다.
- **PC 기준 연결은 로그끼리만 가능합니다.** LDAP에는 `pc` 컬럼이 없어서 사용자 단위로만 붙일 수 있습니다.
- **사용자별 PC 수가 로그마다 다릅니다.**

| 로그 | 사용자별 PC |
|---|---|
| email, http | 사용자마다 본인 PC 1대 |
| file, device | 한 사람이 여러 PC 사용 (최대 417대) |
| logon | 다른 사람의 PC에 로그인한 기록도 있음 |

- **device와 file은 265명만 기록돼 있습니다.** 나머지 735명을 0으로 채우면 "사용 안 함"과 "기록 대상 아님"이 구분되지 않습니다.
- **LDAP 정보는 달마다 바뀌지 않습니다.** 이름·직무·부서·팀·상사가 바뀐 사람은 0명이고, 변화는 퇴사(155명)뿐입니다.

## 5. 사용자×날짜 데이터셋을 만든다면

1. **행 기준:** logon의 로그인한 사용자×날짜 330,452개를 행으로 삼습니다. 모든 활동이 이 안에 들어가므로 빠지는 활동이 없습니다.
2. **활동 로그 붙이기:** email, http, device+file을 각각 날짜별로 집계해 컬럼으로 붙입니다.
   - 현재 `email_user_day_merged.csv`는 email만 붙인 상태입니다.
3. **LDAP 정보 붙이기:**
   - 회사/개인 메일 구분에 사용합니다 (현재 적용 중).
   - 직무·팀으로 동료 집단 기준선을 만들 수 있습니다.
   - 퇴사 시점은 미래 정보이므로 **결과 검증용으로만** 사용합니다.
