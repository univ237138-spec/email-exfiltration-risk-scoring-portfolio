# `user_day_baseline_30.csv` 컬럼 정의서

> 대상 파일: `user_day_baseline_30.csv`
> 생성 코드: [build_user_day_baseline_30.py](../src/pipelines/build_user_day_baseline_30.py) (`data` 폴더에서 `python src/pipelines/build_user_day_baseline_30.py`, 약 25초)
> 입력: `user_day_ldap_logon_email.csv`
> 설계: `베이스라인_설계안.md` (8절 추천안 적용)
> 작성일: 2026-09-19

## 개요

| 항목 | 값 |
|---|---|
| 행 | 330,452 (사용자×로그인 활동일, 전체 유지) |
| 컬럼 | 76개 = 입력 34 + `is_scored`, `base_n` + z 지표 12개 × 3 + 규칙형 4 |
| 점수 대상 행 | 308,023 (`is_scored = 1`) |

### 적용한 결정 사항

| # | 결정 | 적용 |
|---|---|---|
| ① | 주말 행 | 평일과 같이 기준선에 포함 |
| ② | 표준편차 하한 | 모든 z 지표에 `max(sd, 1)` (`email_cnt` 포함) |
| ③ | 참고용 지표 | z점수까지 생성 |
| ④ | 파일 구성 | 이메일·logon 한 파일, 컬럼 이름으로 구분 |

## 1. 입력 컬럼 (34개)

[user_day_ldap_logon_email_컬럼정의서.md](data_dictionary_user_day.md)와 같습니다.

## 2. 공통 컬럼 (2개)

| 컬럼 | 의미 |
|---|---|
| `is_scored` | 점수 대상 행이면 1. 조건: `active_day_seq > 10` 이고 `days_since_first >= 30` |
| `base_n` | 기준선에 들어간 활동일 수 (10~30). `active_day_seq ≤ 10`이면 비어 있음 |

## 3. z 지표 (12개 × 3 = 36개)

지표마다 컬럼 3개가 붙습니다.

| 컬럼 | 의미 | 비어 있는 행 |
|---|---|---|
| `{지표}_mu` | 당일 제외 직전 30개 활동일(최소 10일)의 평균 | `active_day_seq ≤ 10` (10,000행) |
| `{지표}_sd` | 같은 기간의 표준편차 (표본 표준편차) | 위와 같음 |
| `{지표}_z` | (오늘 값 − `_mu`) ÷ max(`_sd`, 1) | `is_scored = 0` (22,429행) |

| 구분 | 지표 | 용도 |
|---|---|---|
| 점수용 핵심 (이메일) | `corp_ext_send_cnt`, `new_ext_rcpt_cnt`, `corp_ext_att_mail_cnt`, `personal_att_mail_cnt`, `int_rcpt_cnt` | 이메일 위험 점수 |
| 참고용 (이메일) | `email_cnt`, `corp_mail_cnt`, `personal_mail_cnt`, `rcpt_cnt`, `bcc_mail_cnt` | 점수 근거 설명 (점수에는 넣지 않음) |
| 확장 제안 (logon) | `other_pc_logon_cnt`, `night_logon_cnt` | 이메일 점수와 따로 계산 |

## 4. 규칙형 (2개 × 2 = 4개)

| 컬럼 | 의미 | 비어 있는 행 |
|---|---|---|
| `jobkw_mail_flag` | 오늘 구직 키워드 메일이 1건 이상이면 1 | `is_scored = 0` |
| `jobkw_mail_past30` | 당일 제외 직전 30개 활동일 중 구직 메일이 있었던 날 수 | `active_day_seq ≤ 10` |
| `night_mail_flag` | 오늘 야간 메일이 1건 이상이면 1 | `is_scored = 0` |
| `night_mail_past30` | 당일 제외 직전 30개 활동일 중 야간 메일이 있었던 날 수 | `active_day_seq ≤ 10` |

`email_cnt_z`는 기존 파일과 다릅니다. 기존은 하한 없이 계산했고, 이 파일은 하한 1을 적용했기 때문입니다(결정 ②).

### ⑤·⑥ 지표별 표준편차 상태와 z ≥ 2 비율 (점수 대상 행)

- 2010-01~05는 내부자 사건이 없는 정상 기간입니다(점수 대상 82,742행). 전체 기간과 비율이 거의 같습니다.
- **`int_rcpt_cnt`는 z ≥ 2가 약 5%**로 핵심 지표 중 가장 높습니다. 값이 크고(평균 5.3명) 오른쪽으로 긴 분포라 표준편차 하한이 거의 적용되지 않기 때문입니다. 점수 구간을 정할 때 다른 지표보다 높은 경계가 필요할 수 있습니다.
- 드문 지표(`corp_ext_att_mail_cnt`, logon 확장 2개)는 하한 적용 비율이 97% 이상입니다. 이 지표들의 z는 사실상 "평소보다 몇 건 더"를 뜻합니다.
